Columns

A column is a key, a header label, a cell renderer, and a set of optional projections. The projections are what turn features on: declaring a sort key is what makes a column sortable, filterable, groupable and exportable at once.

#The shape of a column

GridColumn::new takes the three things every column needs; the rest are builder methods that return Self.

Constructor
GridColumn::new(
    key: &'static str,        // stable identity: sort, filter, persistence
    label: &'static str,      // header text, and the CSV/Excel header
    render: fn(&T) -> Element, // the cell body
)

render is a plain fn pointer, not a closure, which is what keeps GridColumn<T> Clone + PartialEq so Dioxus can diff props. It also means a cell cannot close over your component's state. That is not a limitation in practice: everything a cell needs comes from the row, and row-specific interactivity belongs in actions or on_row_click, which are event handlers and do capture.

The key must be stable across releases if you use persist_key. A saved layout referencing a key that no longer exists is dropped silently, so renaming a key loses that column's saved width and position but never breaks the grid.

#Builders

BuilderSignatureWhat it enables
.sortablefn(&T) -> StringText sort key. Also enables filtering, grouping, Set-filter distinct values and CSV export for this column.
.sortable_numfn(&T) -> f64Numeric sort key. Wins over .sortable when both are present. Enables numeric filter operators and aggregates.
.editablefn(&T) -> StringInline editing. The projection seeds the editor with the cell's current text.
.aggregateAggregateA footer cell summarising this column over the filtered set.
.filterFilterKindPicks the filter control explicitly instead of inferring it.
.csvfn(&T) -> StringAn export-only projection, for when the display differs from what belongs in the file.
.width&'static strApplied as a min-width, e.g. "12rem".
.right—Right-align the cell and header.
.center—Centre-align the cell and header.
.mobile_hidden—Hide the column below the md breakpoint.
Sortable implies filterable, and groupable. The filter stage, the group-by menu and CSV export all reuse the sort projection, because a column you can order is by definition a column whose values can be compared and read. There is no second set of configuration to keep in sync.

#Rendering cells

The renderer returns an Element, so a cell can be anything — text, a badge, a nested component, an image.

Cell renderers
let columns = vec![
    // Plain text.
    GridColumn::new("sku", "SKU", |p: &Product| rsx! { "{p.sku}" }),

    // Markup.
    GridColumn::new("name", "Name", |p: &Product| rsx! { strong { "{p.name}" } })
        .sortable(|p: &Product| p.name.clone()),

    // Formatted display, numeric sort. The display string and the sort key
    // are independent, so "$1,299.00" still orders numerically.
    GridColumn::new("price", "Price", |p: &Product| rsx! { "${p.price:.2}" })
        .sortable_num(|p: &Product| p.price)
        .right(),
];

This separation is the point. A column that formats currency, renders a status pill or shows a relative date still sorts and filters on the underlying value, because the projection is declared next to the renderer rather than derived from it.

#Projection precedence

A column can carry several projections. When the engine needs a comparable value it resolves them in a fixed order, so you only declare what differs from the default:

OperationPrecedence
Sort, filter, groupsort_num → sort_key
Aggregatesort_num (Count ignores the column entirely)
Export cellcsv → sort_key → sort_num → empty

A column with none of the three renders fine but is inert: no sort button, no filter, and an empty cell in the exported file. That is the right default for a column of buttons or thumbnails.

#Inline editing

.editable(…) makes the cell open an input on double-click. Enter or blur commits, Escape cancels. Only one cell edits at a time.

Editable column plus handler
GridColumn::new("name", "Name", |p: &Product| rsx! { strong { "{p.name}" } })
    .sortable(|p: &Product| p.name.clone())
    .editable(|p: &Product| p.name.clone()),

Committing fires the grid's on_edit with a CellEdit<T> — the row, the column key, and the new value as a String. The grid does not parse or apply it. It holds rows behind an Rc and has no way to mutate them, so the host is always the single writer.

The value is always a String. A numeric or date column hands you the raw text the user typed. Parse it yourself and reject what does not parse — the grid deliberately has no opinion about your field types.

#Footer aggregates

.aggregate(Aggregate::…) adds a footer cell for the column, computed over the current filtered set — every matching row, not just the visible page. Narrowing a filter changes the total, turning the page does not.

VariantFooter captionNotes
Aggregate::SumTotalNeeds sort_num.
Aggregate::AvgAverageNeeds sort_num.
Aggregate::MinMinimumNeeds sort_num.
Aggregate::MaxMaximumNeeds sort_num.
Aggregate::CountCountCounts rows; works on any column.
A summed column
use grid_dioxus::{Aggregate, GridColumn};

GridColumn::new("price", "Price", |p: &Product| rsx! { "${p.price:.2}" })
    .sortable_num(|p: &Product| p.price)
    .aggregate(Aggregate::Sum),

A numeric aggregate over a column with no numeric projection yields nothing rather than zero — an empty result is honest, a zero would be a lie about text data. When grouping is active the same aggregates also produce per-group subtotals, using identical semantics so the numbers reconcile with the footer.

#Export projections

Export walks csv → sort_key → sort_num. Reach for .csv(…) when the on-screen cell is not what belongs in a spreadsheet — a rendered badge whose sort key is an internal enum, or a currency cell you want unformatted.

Diverging display and export
GridColumn::new("status", "Status", |o: &Order| rsx! {
        span { class: "badge", "{o.status.label()}" }
    })
    .sortable(|o: &Order| o.status.rank().to_string())  // orders by workflow stage
    .csv(|o: &Order| o.status.label().to_string()),  // exports the human label

The header row of the exported file uses each column's label. Hidden columns still export — the column chooser hides, it never removes, so a hidden column's sort and filter also keep applying.

#Width, alignment and mobile

.width("12rem") is emitted as a min-width, so a long cell can still grow rather than crushing its neighbours. A user's drag-resize overrides it, and persist_key remembers that.

.right() and .center() set the column's GridAlign, which the renderer surfaces as data-align="end" or data-align="center" on the cell. The grid does not apply text-align itself — that is your CSS, per the styling contract. Right-align numbers; it is what makes a column of figures scannable.

.mobile_hidden() marks a column as inessential on narrow screens. The cell is still emitted, carrying data-hide-mobile, and your stylesheet decides the breakpoint.

#What the user can change

Beyond what you declare, the grid lets the user reorder columns by dragging headers, resize them with the header handles, pin them to the left, and hide them from the column chooser. Pass persist_key to save all four to localStorage:

Persisting layout
DataGrid {
    rows,
    columns,
    row_id: |p: &Product| p.id.to_string(),
    persist_key: Some("products-grid"),
}

Stored keys are re-mapped onto the live columns on load and anything unknown is dropped, so shipping a release that renames or removes a column cannot break a returning user's grid.

#Card and custom row slots

Two props let you replace the body while keeping everything else. Both are Option<fn(&T) -> Element>, so they need the same as fn(…) coercion described in the quickstart.

PropReplaces
cardThe card body in gallery view. When None, a card is auto-built from the columns.
rowThe per-column cells in list view, with one full-width cell you own.

In both cases the checkbox, kebab, row click, header sorting, search, filtering and pagination keep working — you are replacing the cell layout, not the grid. Keep your columns declared either way, since header sorting and filtering still read them.

Set no_card_toggle: true for data where a gallery view is meaningless — a permission matrix, a ledger — so the toggle is not offered. grid_default: true starts in card view instead.
