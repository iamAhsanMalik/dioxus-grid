Live demo

The example app from the repository, compiled to wasm and running below. It is a single component of about sixty lines over a forty-two-row product list — everything you see comes from what the four columns declare.

#What to try

  • Click a header to sort, then click it twice more — ascending, descending, back to the dataset's own order.
  • Shift-click a second header to add it as a tie-breaker after the primary sort.
  • Open the funnel on Category: it is a Set filter, so the choices are the column's distinct values.
  • Filter Price or Stock numerically, and watch the Price footer total follow the filtered set rather than the visible page.
  • Double-click a name to edit it in place. The commit fires an event; the app applies it to its own signal.
  • Select a few rows, then select a whole page, then page forward — the selection accumulates and the bulk bar appears.
  • Drag a header to reorder, drag its edge to resize, and hide a column from the chooser.
  • Switch to card view. Search, filters, sort, page and selection all survive the switch.
The demo ships the reference stylesheet. None of this appearance comes from the crate — grid-dioxus contains no CSS. The demo's stylesheet is examples/basic/assets/grid.css, which is also the file to copy as a starting point. See styling.

#The source

The columns are the interesting part. Each carries its own projections, and the grid reads them — the app never writes table markup:

examples/basic/src/main.rs
let columns = vec![
    GridColumn::new("name", "Name", |p: &Product| rsx! { strong { "{p.name}" } })
        .sortable(|p: &Product| p.name.clone())
        .editable(|p: &Product| p.name.clone()),
    GridColumn::new("category", "Category", |p: &Product| rsx! { "{p.category}" })
        .sortable(|p: &Product| p.category.clone())
        .filter(FilterKind::Set),
    GridColumn::new("price", "Price", |p: &Product| rsx! { "${p.price:.2}" })
        .sortable_num(|p: &Product| p.price)
        .aggregate(Aggregate::Sum),
    GridColumn::new("stock", "Stock", |p: &Product| rsx! { "{p.stock}" })
        .sortable_num(|p: &Product| p.stock as f64),
];

Four columns, and between them: sorting on all four, a set filter, numeric filters, an editable cell, a footer total, group-by candidates, and the projections export uses. No feature here needed a second piece of configuration.

The full file is examples/basic/src/main.rs in the repository.

#Running it locally

Clone the repository and serve the example with the Dioxus CLI. Editing the example, the renderer or the reference stylesheet hot-reloads.

Terminal
git clone https://github.com/iamAhsanMalik/dioxus-grid
cd dioxus-grid
dx serve --package grid-basic-example --web

To compile the type-erased render path instead — the one wasm builds select by default, and the reason a multi-row-type app does not ship a copy of the renderer per row type — add the feature:

Terminal
dx serve --package grid-basic-example --web --features force-erased

Both paths behave identically; only the generated code differs. See bundle size for why there are two and when to override the choice.
