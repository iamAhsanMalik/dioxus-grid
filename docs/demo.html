Live demo

The example app from the repository, compiled to wasm and running below. It is a single component over a 124-row order list — the avatars, status chips and star ratings all come from what the eight columns declare, and none of it is styled by the crate.

#What to try

  • Click a header to sort, then click it twice more — ascending, descending, back to the dataset's own order.
  • Shift-click a second header to add it as a tie-breaker after the primary sort.
  • Open the funnel on Status or Channel: both are Set filters, so the choices are the column's distinct values.
  • Filter Total by range, or Rating with the star picker, and watch the Total and Items footer sums follow the filtered set rather than the visible page.
  • Double-click a customer name to edit it in place. The commit fires an event; the app applies it to its own signal.
  • Select a few rows, then select a whole page, then page forward — the selection accumulates and the bulk bar appears.
  • Drag a header to reorder, drag its edge to resize, and hide a column from the chooser.
  • Switch to card view. Search, filters, sort, page and selection all survive the switch.
  • Narrow the window: Placed and Rating drop out, because those columns declare themselves hideable on small screens.
The demo ships the reference stylesheet. None of this appearance comes from the crate — grid-dioxus contains no CSS. The grid itself is styled by examples/basic/assets/grid.css, which is the file to copy as a starting point; the avatars, chips and star ratings are the example's own demo.css. See styling.

#The source

The columns are the interesting part. Each carries its own projections, and the grid reads them — the app never writes table markup:

examples/basic/src/main.rs
// Rich cell content is just rsx — the grid does not know what a cell holds.
GridColumn::new("customer", "Customer", |o: &Order| rsx! {
    div { class: "cust",
        span { class: "avatar", "{initials(&o.customer)}" }
        div {
            strong { "{o.customer}" }
            span { class: "sub", "{o.region}" }
        }
    }
})
.sortable(|o: &Order| o.customer.clone())
.editable(|o: &Order| o.customer.clone()),

// A Set filter builds its checklist from the string sort key, so this sorts
// by label. Numeric sorting and a Set filter are mutually exclusive.
GridColumn::new("status", "Status", |o: &Order| rsx! {
    span { class: "chip chip-{o.status.tone()}", "{o.status.label()}" }
})
.sortable(|o: &Order| o.status.label().to_string())
.filter(FilterKind::Set),

GridColumn::new("total", "Total", |o: &Order| rsx! { strong { "${o.total:.2}" } })
    .sortable_num(|o: &Order| o.total)
    .filter(FilterKind::Range)
    .aggregate(Aggregate::Sum)
    .right()
    .width("7rem"),

Eight columns, and between them: sorting on every one, Set, Range, Rating and DateRange filters, an editable cell, two footer aggregates, alignment and width hints, and columns that hide on narrow screens. No feature here needed a second piece of configuration.

The full file is examples/basic/src/main.rs in the repository.

#Running it locally

Clone the repository and serve the example with the Dioxus CLI. Editing the example, the renderer or the reference stylesheet hot-reloads.

Terminal
git clone https://github.com/iamAhsanMalik/dioxus-grid
cd dioxus-grid
dx serve --package grid-basic-example --web

To compile the type-erased render path instead — the one wasm builds select by default, and the reason a multi-row-type app does not ship a copy of the renderer per row type — add the feature:

Terminal
dx serve --package grid-basic-example --web --features force-erased

Both paths behave identically; only the generated code differs. See bundle size for why there are two and when to override the choice.
