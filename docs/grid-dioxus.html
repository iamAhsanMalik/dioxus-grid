grid-dioxus

The Dioxus renderer over the three headless crates. It ships behavior and stable class hooks and no CSS. This is normally the only dependency you need: it re-exports grid_core, grid_plugin_api and grid_state, so you can build queries, providers and state without adding them to your manifest.

#The minimal grid

Three required props. This is the compile-tested example from grid-dioxus/tests/readme_example.rs, which exists so the docs cannot drift from the real API.

a working grid
use std::rc::Rc;

use dioxus::prelude::*;
use grid_dioxus::{DataGrid, GridColumn};

#[derive(Clone, PartialEq)]
struct Row { id: u32, name: String, qty: i64 }

fn search_text(r: &Row) -> String { r.name.clone() }

#[component]
fn Demo() -> Element {
    let rows: Rc<[Row]> = vec![Row { id: 1, name: "Widget".into(), qty: 12 }].into();
    let columns = vec![
        GridColumn::new("name", "Name", |r: &Row| rsx! { "{r.name}" })
            .sortable(|r| r.name.clone()),
        GridColumn::new("qty", "Qty", |r: &Row| rsx! { "{r.qty}" })
            .sortable_num(|r| r.qty as f64),
    ];
    rsx! {
        DataGrid {
            rows,
            columns,
            row_id: |r: &Row| r.id.to_string(),
            search_text: Some(search_text as fn(&Row) -> String),
            selectable: true,
        }
    }
}

#Two gotchas, up front

Both come from the same design constraint, so they are worth understanding together rather than hitting one at a time.

rows is Rc<[T]>, not Vec<T>

The dataset is shared by reference-counted pointer so that neither the parent nor the grid ever clones the whole thing — only the visible page's rows are materialised. Vec<T> would mean a full copy on every render.

building the rows prop
let rows: Rc<[Row]> = my_vec.into();       // or Rc::from(my_vec)
let rows: Rc<[Row]> = vec![a, b, c].into();

Some props are fn pointers, not closures

Dioxus requires props to be PartialEq so it can skip re-renders, and a boxed closure is not comparable. So render, the sort keys, row_id, search_text, actions, card and row are all plain fn pointers.

A non-capturing closure coerces to a fn pointer, so row_id: |r: &Row| r.id.to_string() just works. But when the prop's type is Option<fn(&T) -> String>, inference has nothing to coerce toward inside the Some, and you must say so:

the Option coercion
// does not compile — closure inside Some, no target type
search_text: Some(|r: &Row| r.name.clone()),

// works — name a fn and coerce it
search_text: Some(search_text as fn(&Row) -> String),

// same for actions
actions: Some(row_actions as fn(&Row) -> Vec<GridAction>),
Capturing closures are not an option here. If a cell needs data from the surrounding scope, that data belongs in T. Row-specific interactivity goes through actions and on_action instead, which are EventHandlers and may capture freely.

The grid stays clock-free. today is a prop rather than a now() call because reading the clock inside a component makes it untestable and non-deterministic, and because the correct "today" depends on the user's timezone, which the host knows and the grid does not.

Export

PropTypePurpose
export_filenameOption<&'static str>Enables the toolbar export of the current view — rows after search, filters and sort, across all pages. The value is the download filename. None hides the button.
on_export_signedOption<EventHandler<GridQuery>>Adds a "Signed PDF" item that fires with the current query, for your backend to render, sign and return.

Export can also cover the whole dataset rather than the filtered view — the export menu is a format choice crossed with a scope choice. CSV needs no features; Excel and PDF need export-rich. See bundle size for why you probably want that off in wasm, and why signing is a server concern.

Remote mode

PropTypePurpose
on_queryOption<EventHandler<GridQuery>>Fires whenever the effective query changes. Its presence puts the grid in remote mode.
remote_pageOption<GridPage<T>>The page you fetched for the latest query. None while loading.

In remote mode the grid stops querying rows locally and draws exactly the page you hand it, so rows may be empty. The host runs its own async fetch — the grid never picks a runtime or an HTTP client. This is how a grid scales past what a browser can hold: the server filters, sorts and paginates, and the browser holds one page.

#GridColumn

The view-side column type. It is a superset of ColumnDef — the grid derives the engine columns from these — with the rendering concerns core deliberately omits.

grid_dioxus::GridColumn
impl<T: Clone + PartialEq + 'static> GridColumn<T> {
    pub fn new(key: &'static str, label: &'static str,
               render: fn(&T) -> Element) -> Self;

    pub fn sortable(self, f: fn(&T) -> String) -> Self;
    pub fn sortable_num(self, f: fn(&T) -> f64) -> Self;  // wins over sortable
    pub fn csv(self, f: fn(&T) -> String) -> Self;
    pub fn editable(self, f: fn(&T) -> String) -> Self;
    pub fn aggregate(self, agg: Aggregate) -> Self;
    pub fn filter(self, kind: FilterKind) -> Self;
    pub fn right(self) -> Self;
    pub fn center(self) -> Self;
    pub fn width(self, w: &'static str) -> Self;   // e.g. "12rem" → min-width
    pub fn mobile_hidden(self) -> Self;
}

A few behaviors that are easy to miss:

  • Sortable is the master switch. A column with a sort key is sortable, filterable and groupable; one without is none of those. sortable_num also marks the column numeric, which drives the operator list and the inferred filter control.
  • csv is for when display differs from data. Export falls back to sort_key, then sort_num; a column with none of the three exports as an empty cell. Set csv when the cell renders a badge or an icon whose text is not what belongs in the file.
  • width is a min-width, so long content does not crush its neighbours. A user drag overrides it with a fixed width.
  • aggregate uses the numeric projection, over the current filtered set — not the page. Count is type-agnostic.

FilterKind

Which control the filter popover shows. Defaults to Auto, which infers Number from a sort_num projection and Text otherwise. Set it explicitly when the data has a shape the projection cannot convey.

VariantControl
AutoInferred from the column.
TextFree text: contains / equals / starts-with.
NumberNumeric operators with a number input.
RatingA 0–5 star picker filtering by "rating ≥ N".
HasValueA present / absent toggle over the projection.
RangeA min–max numeric range, both bounds optional.
SetA checkbox list of the column's distinct values, derived from the dataset.
DateRangeTwo date pickers. Packs to the same min|max range, lexicographic on ISO YYYY-MM-DD — which sorts chronologically.

All of them drive the same underlying filter stage over the column's projection. Only the input differs, which is why a rating picker and a numeric range need no special handling in the engine.

#GridAction

grid_dioxus::GridAction
impl GridAction {
    pub fn new(key: &'static str, label: impl Into<String>) -> Self;
    pub fn danger(key: &'static str, label: impl Into<String>) -> Self;
    pub fn icon(self, path: &'static str) -> Self;   // SVG path, 24×24, stroke-based
    pub fn quick(self) -> Self;      // also an inline icon button (needs an icon)
    pub fn disabled(self) -> Self;
    pub fn no_bulk(self) -> Self;    // exclude from the bulk bar
}

danger sets data-variant="danger" on the rendered item, so destructive entries are yours to style rather than pre-coloured.

no_bulk matters once you wire on_bulk_action. The bulk bar is derived from the actions common to every selected row, and some actions do not make sense applied to a set — an "Edit" that opens one record's form, for instance. Mark those no_bulk and they stay in the per-row kebab only.

#CellEdit

grid_dioxus::CellEdit
pub struct CellEdit<T: Clone + PartialEq + 'static> {
    pub row: T,
    pub key: &'static str,
    pub value: String,
}

The value is the raw text the user typed. You parse it into your field and update your own data — the grid never mutates the rows, because they are shared by Rc and it does not know how to validate your domain. Rejecting a bad edit is simply not applying it.

#AdaptiveDataGrid

Takes the exact same props — it is DataGridProps — and is a thin pass-through, so there is one grid implementation to maintain. What it adds is two defaults chosen from the data volume:

  • Density. At or below 30 rows it picks Minimal; above that, Full. An explicitly non-default density from the caller always wins.
  • Initial view. At or below 30 rows it starts in gallery view, since cards read better than a sparse table. It only seeds the starting mode — the user's toggle always wins thereafter.

In remote mode it uses the fetched page's total rather than rows.len(), and stays in list view.

rows.len() is a weak signal, so treat this as a default. A 12-row filtered slice of 50,000 still wants the full controls — the user needs the filter funnels precisely because the dataset is large. Where the row count does not reflect the dataset's real size, pass density explicitly or just use DataGrid.

#Date and DateRangePicker

The control behind the DateRange filter, exported because it is useful on its own.

grid_dioxus::Date
pub struct Date { pub year: i32, pub month: u32, pub day: u32 }

impl Date {
    pub fn new(year: i32, month: u32, day: u32) -> Self;
    // Lenient ISO YYYY-MM-DD parse; None on anything malformed.
    pub fn parse(s: &str) -> Option<Date>;
}

DateRangePicker takes from and to as ISO strings — either side may be empty — plus an optional today, and fires onchange with the new (from, to) pair on Apply, on a preset, or on Clear. Like the grid, it never reads the clock itself.

#ExportData and ExportFormat

grid_dioxus::grid_export
pub struct ExportData {
    pub headers: Vec<String>,
    pub rows: Vec<Vec<String>>,
    pub title: String,   // PDF heading / sheet name; usually the filename stem
}

pub enum ExportFormat { Csv, Xlsx, Pdf }

impl ExportFormat {
    pub fn extension(self) -> &'static str;
}

Export flattens to strings before it reaches a format encoder, which is why adding Xlsx and Pdf behind a feature does not touch the grid's own code paths.

#Features

FeatureEffect
webBrowser glue. Enables dioxus/web and the localStorage persistence behind persist_key. On native, every storage call is a no-op — so layout simply is not persisted there, which is the desired behavior.
export-richClient-side Excel and PDF encoders. CSV always works without it.
force-mono / force-erasedOverride the render path. At most one; both is a compile error. See bundle size.

Note what persist_key saves and what it does not: column order, widths, pins and hidden columns — layout. Filters, sort and page are deliberately not persisted, because they are query state. Returning to a screen and finding it silently filtered is a bug, not a feature.
