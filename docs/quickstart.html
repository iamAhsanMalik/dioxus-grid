Quickstart

A working grid is one dependency, a row type, a list of columns and three props. Everything else — search, sorting, filtering, pagination, selection — comes from what the columns declare.

#Install

Add grid-dioxus only. It re-exports grid_core, grid_state and grid_plugin_api, so you never add the headless crates to your own manifest unless you want to depend on them without the renderer.

Cargo.toml
[dependencies]
dioxus = { version = "0.7", features = ["web"] }
grid-dioxus = { version = "0.1", features = ["web"] }

The web feature adds the browser glue — it is what persists a user's column layout to localStorage. Requires Rust 1.85 or newer.

#Your first grid

This is the example from the README. It is compile-tested in the repository, so it will not drift from the API.

src/main.rs
use std::rc::Rc;

use dioxus::prelude::*;
use grid_dioxus::{DataGrid, GridColumn};

#[derive(Clone, PartialEq)]
struct Row {
    id: u32,
    name: String,
    qty: i64,
}

fn search_text(r: &Row) -> String {
    r.name.clone()
}

#[component]
fn Demo() -> Element {
    let rows: Rc<[Row]> = vec![Row { id: 1, name: "Widget".into(), qty: 12 }].into();
    let columns = vec![
        GridColumn::new("name", "Name", |r: &Row| rsx! { "{r.name}" }).sortable(|r| r.name.clone()),
        GridColumn::new("qty", "Qty", |r: &Row| rsx! { "{r.qty}" }).sortable_num(|r| r.qty as f64),
    ];
    rsx! {
        DataGrid {
            rows,
            columns,
            row_id: |r: &Row| r.id.to_string(),
            search_text: Some(search_text as fn(&Row) -> String),
            selectable: true,
        }
    }
}

That renders a searchable, sortable, filterable, paginated table with selection checkboxes. No table markup, and no CSS yet — see styling for the class contract and a reference stylesheet to copy.

#The three required props

Everything else on DataGrid has a default.

PropTypeWhy
rows Rc<[T]> The dataset, shared by reference-counted pointer. Neither your component nor the grid ever clones the whole thing.
columns Vec<GridColumn<T>> What to render, and which projections exist for sorting, filtering, export and aggregation.
row_id fn(&T) -> String Stable row identity. Selection and action routing are keyed by it.

#Why rows is an Rc, not a Vec

The grid queries over indices and materialises only the visible page. A one-million-row dataset therefore costs one refcount bump per render plus page_size row clones — not a million. Passing a Vec would force a full copy on every re-render, which is exactly the cost the design is avoiding, so the prop type makes that impossible to do by accident.

Both of these work:

Building the Rc
let rows: Rc<[Row]> = my_vec.into();      // Vec<T> → Rc<[T]>
let rows = Rc::from(products());          // same thing, explicit

If your data lives in a signal, build the Rc at the call site: rows: Rc::from(products()). The grid mirrors the prop into an internal signal, so replacing the Rc re-runs the query and the table updates.

#The fn-pointer coercion

Columns and several props hold plain fn pointers rather than boxed closures. That is deliberate: it keeps GridColumn<T> and the props struct Clone + PartialEq, which is what lets Dioxus skip re-renders.

The consequence is that optional fn-pointer props — search_text, actions, card, row — are Option<fn(…)>, and Rust will not infer the coercion from a non-capturing closure inside Some(...). Write the cast:

Coercing a closure to a fn pointer
// A named fn — cast it:
search_text: Some(search_text as fn(&Row) -> String),

// An inline closure — parenthesise, then cast:
search_text: Some((|p: &Product| format!("{} {}", p.name, p.category))
    as fn(&Product) -> String),

actions: Some((|_p: &Product| vec![GridAction::new("view", "View")])
    as fn(&Product) -> Vec<GridAction>),
The closure must not capture. A fn pointer has no environment, so anything the projection needs has to come from the row argument. Event handlers (on_action, on_edit, on_selection) are EventHandlers, not fn pointers — those capture freely.

Required fn-pointer props like row_id are not wrapped in Option, so a bare closure is fine there and no cast is needed.

#Props you will reach for next

PropTypeEffect
search_textOption<fn(&T) -> String>Haystack for the global search box. None hides the box.
selectableboolAdds the row and select-page checkboxes.
page_sizeusizeRows per page. Defaults to 10; clamped to at least 1.
actionsOption<fn(&T) -> Vec<GridAction>>Builds the row kebab menu. None hides the action column.
on_actionEventHandler<(&'static str, T)>Fires with the action key and the row.
on_row_clickEventHandler<T>Row click. Checkbox and kebab clicks do not bubble here.
on_editEventHandler<CellEdit<T>>An inline edit was committed. Requires an .editable(…) column.
on_selectionEventHandler<Vec<String>>The selected-id set changed.
on_bulk_actionEventHandler<(&'static str, Vec<T>)>Auto-derives a bulk bar from the actions common to every selected row.
loadingboolRenders the loading state instead of rows.
empty_labelStringEmpty-state text. Defaults to "No records match."
toolbarOption<Element>Extra toolbar content, always rendered.
export_filenameOption<&'static str>Enables the export button. The value is the download filename.
persist_keyOption<&'static str>Saves column layout (order, widths, pins, hidden) under this key.
densityGridDensityFull (default) or Minimal, which strips the enterprise chrome.

persist_key saves layout only. Search, filters, sort and page are query state, not layout, and are intentionally not persisted — a returning user should see the whole dataset arranged the way they left it, not a stale filter they have forgotten about.

#Handling edits and actions

The grid never mutates your rows. It shares them by Rc, so it cannot; an inline edit or a destructive action fires an event and you apply it to your own state. That keeps the grid out of your data flow entirely.

Applying an edit
let mut products = use_signal(seed);

rsx! {
    DataGrid {
        rows: std::rc::Rc::from(products()),
        columns,
        row_id: |p: &Product| p.id.to_string(),
        on_edit: move |edit: grid_dioxus::CellEdit<Product>| {
            if edit.key == "name" {
                if let Some(p) = products.write().iter_mut().find(|x| x.id == edit.row.id) {
                    p.name = edit.value.clone();
                }
            }
        },
    }
}

CellEdit<T> carries the row, the column key, and the raw value string the user typed. You parse it into your field — the grid has no idea what type the cell holds.
