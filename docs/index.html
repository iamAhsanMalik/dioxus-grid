Documentation

A headless data grid for Rust.

The engine is framework-agnostic; the renderer targets Dioxus. Sorting, per-column filters, pagination, selection, grouping, inline editing and CSV export — with no styling shipped, so the grid looks like your app rather than like a widget library.

Quickstart See it running

#Install

One dependency is enough. grid-dioxus re-exports the three headless crates, so you do not need to add them yourself.

Cargo.toml
[dependencies]
grid-dioxus = { version = "0.1", features = ["web"] }

Requires Rust 1.85 or newer.

#How it fits together

The data operations, the interaction state and the rendering are three separate concerns, in three separate crates. That split is the reason the engine can be unit tested without a browser, and the reason a non-Dioxus front end only needs grid-core.

grid-core

Column definitions, the query model, and the filter, sort and paginate pipeline. No UI, no framework.

grid-state

Interaction state: selection, sort cycling, paging and view mode, plus the intents a renderer calls.

grid-plugin-api

Composable query stages — column filters, multi-sort, aggregates — and the data-provider seam.

grid-dioxus

The Dioxus renderer. Ships behavior and stable class hooks, and no CSS.

#What "headless" means here

The renderer emits structure, behavior and state, and nothing about appearance. Every element carries a stable dxg-* class name, state lives in data-* attributes, and the only inline styles are values that can only be known at render time, like a dragged column's width.

You write the CSS. There is a reference stylesheet to copy as a starting point, and the styling guide documents the full contract.

Sortable implies filterable. A column that declares a sort key is filterable with no extra configuration, because the filter stage reuses the same projection.
